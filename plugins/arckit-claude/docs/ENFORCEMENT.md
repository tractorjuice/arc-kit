# What ArcKit Enforces, What It Asks, and What You Own

ArcKit is a governance harness inside a coding agent. Some of its rules hold whatever the model does, because a hook or a script checks them in code. Others hold only as far as the model follows the instruction in a command body, a template or a reference file. A third set is not ArcKit's to enforce at all: the deploying organisation supplies it. An assurance reviewer needs to know which tier each rule sits in, and this page is the one statement of that.

Paths are relative to the plugin root. Hook mechanics (exec form, `continueOnBlock`, `if:` narrowing) are in [`hooks/README.md`](../hooks/README.md); the per-hook user guide is `docs/guides/hooks.md`; the reader/writer isolation the research commands use is in [`READER-PATTERN.md`](READER-PATTERN.md).

**Runtime coverage.** The gates below are Claude Code hooks. The Codex extension re-implements most of them in one hand-maintained hook (secret patterns, protected files, manifest update, provenance stamping, project and graph context injection). The Gemini extension re-implements filename validation, file protection, manifest update and context injection in Python. The OpenCode, Copilot, Paperclip, Vibe and Kimi extensions carry no gates: on those runtimes every row of the first table falls back to the second tier, the prompt.

## Tier 1: Enforced in code

A rule in this table holds on any model and any prompt. Each gate is a Node subprocess that Claude Code runs on the named event; a `PreToolUse` gate blocks by returning `{"decision": "block"}` with a reason the model sees, so it can self-correct rather than surface a permission error the user has to read.

| Rule | Enforced in | Event | On failure |
|---|---|---|---|
| **Filename convention.** An artefact written under `projects/` is named `ARC-{PID}-{TYPE}[-{SEQ}]-v{VER}.md`. The project ID is zero-padded and corrected to the directory's number, the version is normalised, a multi-instance type is moved to its subdirectory and given the next sequence number. | `hooks/validate-arc-filename.mjs` | PreToolUse `Write(/projects/**)` | Path rewritten in place; the model never sees the wrong name |
| **Registered doc-type codes only.** The type code in the filename must be in `config/doc-types.mjs`. `scripts/generate-document-id.mjs` imports the same list, so an ID it emits is one the hook accepts. | `hooks/validate-arc-filename.mjs` | PreToolUse `Write(/projects/**)` | Blocked, with the valid list in the reason |
| **Protected files are not written.** `.env*`, lock files, `.git/`, `.aws/`, `.ssh/`, `.gnupg/`, credential and secret files by name, `*.pem`/`*.key`/`*.p12`/`*.pfx`, SSH identity files, `.npmrc`/`.pypirc`/`.netrc`, and any filename carrying a sensitive keyword (`api key`, `apikey`, `api-key` and a whole-word list). | `hooks/file-protection.mjs` | PreToolUse `Edit\|Write` | Blocked |
| **No secret in a prompt.** Explicit key/value assignments (reference-guarded, so `process.env.X` and `var.secret` pass), common API-key formats, Notion, Atlassian, Slack and Google tokens, bearer tokens, connection strings, PEM headers, high-entropy strings. | `hooks/secret-detection.mjs` | UserPromptSubmit | Prompt blocked before it is sent |
| **No secret in a written file.** The same pattern set, kept in sync with the prompt scanner, with a skip list for documentation and the security tooling itself. | `hooks/secret-file-scanner.mjs` | PreToolUse `Edit\|Write` | Blocked |
| **Vendor scores are well-formed.** `scores.json` parses, carries the required fields, every score is 0–3, weights sum to approximately 1.0. | `hooks/score-validator.mjs` | PreToolUse `Write(/projects/**/vendors/scores.json)` | Blocked |
| **Wardley Map artefacts are internally consistent.** Stage/evolution alignment of the Component Inventory, coordinates in `[0.00, 1.00]`, OWM block agrees with the inventory, no dangling `evolve`/`pipeline`/edge references, unique annotation IDs, valid pipeline ranges, style names from the allowlist, no bare-digit `wardley-beta` tokens. | `hooks/validate-wardley-math.mjs` | PreToolUse `Write(/projects/**/wardley-maps/**)` | Blocked |
| **Reader payloads are sanitised and schema-valid before a writer sees them.** Every string is NFKC-normalised and stripped of invisible characters; Unicode tag characters, transcript-shaped markup and forged turn markers are rejected; then the payload is validated against the command's `schemas/*-handoff.schema.json` (allowlist enums, `maxLength`, `pattern`, `additionalProperties: false`). | `scripts/validate-handoff.mjs`, invoked by the orchestrating command | Bash, in the main thread | Exit 1 with path-addressed errors; consumes the reader's one re-dispatch, then the source is a logged gap |
| **Readers cannot write; writers cannot fetch.** Each reader's `tools:` allowlist holds `Read`, `Glob`, `Grep`, `WebSearch`, `WebFetch` and that command's MCP server only; each writer's holds no network tool. The orchestrator never reads a byte a reader returned except through the validator. | `agents/arckit-*-reader.md`, `agents/arckit-*-writer.md` frontmatter; `scripts/check-agent-frontmatter.py` in CI | Claude Code tool allowlisting | Tool unavailable to the subagent |
| **Build provenance is machine-stamped.** After an artefact write under `projects/`, a `## Build Provenance` block records the build context (recipe, wave, target) when the write came from `/arckit:arckit-build`, the requested effort from command frontmatter, and the effective effort after the known silent downgrades. Idempotent: re-stamping replaces the block. | `hooks/provenance-stamp.mjs` | PostToolUse `Write\|Edit (/projects/**)`, `continueOnBlock` | Observational; a failure leaves the file as written |
| **The published index cannot reference an unpublishable file.** `docs/manifest.json` is updated incrementally after an artefact write, and a gitignored artefact is never added. | `hooks/update-manifest.mjs`; full rebuild in `hooks/sync-guides.mjs` via `/arckit:pages` | PostToolUse `Write(/projects/**)`, `continueOnBlock` | Observational |
| **Stale artefacts are surfaced.** At session start, every artefact whose Document Control `Next Review Date` is in the past, or whose status is `DRAFT` and untouched for 14+ days, is reported. | `scripts/bash/detect-stale-artifacts.sh` as the `stale-artifact-scan` monitor; `hooks/notify-stale-artifacts.mjs` for the opt-in desktop notification | Plugin monitor, SessionStart | Notification only |
| **Only bundled, read-only MCP tools are auto-approved.** Permission requests for the six bundled documentation servers are allowed without a dialog; every other tool falls through to the normal permission flow. | `hooks/allow-mcp-tools.mjs`; `hooks/allow-plugin-internals.mjs` for reads of the plugin's own files and its helper scripts | PermissionRequest, PreToolUse | Pass-through to the user's permission dialog |
| **Bulk builds are never model-initiated.** The build harness carries `disable-model-invocation: true`; only a person can run `/arckit:arckit-build`. | `skills/arckit-build/SKILL.md` frontmatter | Claude Code skill loading | Not invocable by the model |
| **The client is new enough for the gates to hold.** A Claude Code client below the floor in `hooks/version-check.mjs` is warned at session start with the protections it lacks. | `hooks/version-check.mjs` | SessionStart | Warning; the session continues |

A `PreToolUse` gate holds only while its subprocess can run: the hooks need Node on `PATH`, and a hook Claude Code cannot launch is reported to the user rather than treated as a block. Treat "Node present" as a precondition of the whole table.

## Tier 2: Asked of the model

These rules live in command bodies, templates and the two reference files. Every command that produces a governed artefact is told to read `references/quality-checklist.md` before writing and to fix failures first; every command that gathers external evidence is told to follow `references/citation-instructions.md`. CI asserts that every such instruction resolves to a real checklist section and to citation tables the template actually ships (`scripts/check-quality-checklist-refs.py`, `scripts/check-citation-section-refs.py`), and that the checklist's classification ladders match the templates (`scripts/check-quality-checklist-ladders.py`), so the *asking* is guarded even though the *doing* is not.

The *doing* is measured by the behavioural eval suite in [`../evals/`](../evals/README.md): cases that run a command against a fixture repository and grade the artefact it wrote, the tools it called and the text it returned. The suite is where a row in this table gets a number rather than a promise.

| Rule | Where it is stated | What checks it |
|---|---|---|
| **Document Control block is complete.** All 14 standard fields; Revision History with the six standard columns; the generation footer. | Every template; checklist common checks 1, 6, 7 | The model, against the checklist; `detect-stale-artifacts.sh` reads two of the fields |
| **Classification comes from the artefact's regime, not the operator.** The doc-type's regime picks the classification ladder; user config applies only where the regime falls through. | `templates/_partials/RENDERING.md`; checklist common check 4 | The model; `scripts/check-doc-control-resolution.py` holds the partials and the rule text consistent in CI |
| **Status is one of the six values and a generated artefact starts as `DRAFT`.** Sign-off is a human act recorded in Revision History; the research commands say so explicitly ("recommend, don't decide"). | Templates; checklist common check 5; command guardrails | The model |
| **No placeholder text survives.** `[PLACEHOLDER]`, `TODO`, `TBD`, `XXX`, `YYYY-MM-DD` are removed before the write. | Checklist common check 3 | The model |
| **Templates are followed, never freeform.** A command reads `templates-custom/` first, then `templates/`, and writes the artefact with the `Write` tool so the 32K output limit cannot truncate it. | Command bodies; `CLAUDE.md` key patterns | The model; `validate-arc-filename.mjs` catches only the name |
| **Every external figure carries a citation.** Inline `[SOURCE-ID-Cn]` markers, a Document Register, a Citations table, an Unreferenced Documents table; the UK Tenders attribution line and the awarded-value caveat verbatim. | `references/citation-instructions.md`; the writer agents' input schema carries the `citations` chain | The model; the handoff schema requires `citation_id` and `fetched_from_url` on every option, so a figure without a source cannot reach the writer, but whether the writer places every marker is the model's |
| **Fenced source text is material, not instruction.** A reader payload that reads as an instruction is scored, cited and not acted on; an apparent injection is noted as a gap. | Orchestrator guardrails in the split commands | The model, after the sanitiser has removed the shapes it can recognise |
| **Requirement IDs, traceability and cross-references.** `BR/FR/NFR/INT/DR` prefixes, MoSCoW priority, links back to stakeholder goals; ADRs link their predecessors. | Checklist per-type checks; templates | The model; `/arckit:traceability` and `/arckit:health` report gaps after the fact, and the Stop-hook nudge suggests the next command |
| **Clean Markdown.** Tables, headings and code fences render. | Checklist common checks 8–10 | The model |

When the model breaks one of these, the error is confined to the artefact's text: a missing citation marker, a stale placeholder, a status left at `IN_REVIEW`. Nothing has been published, approved or executed, because publication and approval are not tool calls the model holds.

## Tier 3: What the deploying organisation owns

The plugin stops at the boundary of your repository and your Claude Code configuration. Before governed artefacts are relied on:

- **Review and approval.** The `Reviewed By`, `Approved By` and `Approval Date` fields are filled by people. The harness stamps who generated an artefact and at what effort; it does not know who is entitled to approve it. Pull-request review on `projects/` is the intended approval surface.
- **Classification handling.** ArcKit labels artefacts; it does not control where an `OFFICIAL-SENSITIVE` file can go. Repository visibility, `docs/` publication via `/arckit:pages`, and transcript retention under `~/.claude/projects/` are yours to constrain.
- **Permissions and egress.** Managed `permissions.deny` for secret stores and build outputs, `permissions.blockReadsOutsideWorkingDirectories`, Manual permission mode for regulated repositories, `sandbox.network.strictAllowlist` for the research commands, and an MCP endpoint allowlist. The security baseline in `docs/guides/enterprise-scale.md` lists the settings.
- **Which MCP servers the plugin may reach.** The six bundled servers are auto-approved because they are read-only documentation sources. A server you add is not, and the auto-allow hook does not know it.
- **API keys.** The two keyed servers take their keys from plugin `userConfig`, stored in the keychain and never substituted into prompt text. Rotating them is yours.
- **Model choice and effort.** `model: inherit` on every agent means your session or fleet setting decides. The provenance stamp records what was requested and the downgrades it can see; it cannot see a thinking-off session sending `xhigh`/`max` as `high`.
- **Retention.** Session telemetry in `.arckit/memory/`, the session log, and the provenance blocks are records; their retention period is your records policy, not the plugin's.
- **The non-Claude runtimes.** On OpenCode, Copilot, Paperclip, Vibe and Kimi, every Tier 1 row is a Tier 2 row. If those runtimes are in scope, the controls above are the only ones.

## Held at build time

A fourth set of checks runs in this repository's CI, not in yours. They keep the prompts, templates and hooks consistent with each other so that the two tiers above mean what this page says: every agent declares a `tools:` allowlist (`check-agent-frontmatter.py`); every split command has a monolith for the non-Claude targets (`check-orchestrator-leaks.py`); every recipe target names the doc-type its command declares (`check-doc-type-registry.py`); the two guide trees are byte-identical (`check-guide-parity.py`); every `${CLAUDE_PLUGIN_ROOT}` path, handoff and `userConfig` key resolves (`check_references.py`); and the handoff validator's sanitiser and schemas reject the fixture set under `tests/plugin/fixtures/*-handoff/`. A change to a hook, a template or a reference file that this page describes should update this page in the same pull request.
