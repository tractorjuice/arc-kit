# UK food safety overlay: checks before the summary

Every command in this overlay runs these checks after its last write and before it shows its summary. Each one is something you can look at: a helper's exit code, a field in `status --json`, a line in a file, or what you yourself wrote in this run against what the person said. A check that does not apply to the command running (the summary checks for a document a command does not write, for example) is skipped. If a check fails, put it right as it says, then look again.

For this overlay's documents these checks take the place of the Common Checks in ArcKit's general quality checklist. The body of each document is printed by the helper, and a general rule about headings or tables must never be met by changing it.

## Every document a command writes

1. **`check` passed.** The last `check --doc CODE --project PROJECT --report FILE` for the file as written exited 0. If it exited 1 for a line of the body, the document was written again from a fresh render, never edited by hand between the markers. If the profile, safe methods, own methods or check command had just written the file and `check` exited 1 for a line of its header, that command put the header back to `DRAFT` and `[PENDING]`; what the sign-off command does with a header is item 29.
2. **The body is the render, whole.** The file holds exactly one `UK-FOOD:BEGIN` line and one `UK-FOOD:END` line, and between them the render output and nothing else. Nothing from the pack appears outside them, and no heading outside them is a section's title or starts with a safe method's identifier and title. Outside them the file holds only what the template gives (the title, Document Control, Revision History, the comment above the body and the footer): you added no summary, note, heading or other text of your own, before the markers or after them.
3. **The header says DRAFT.** A document the profile, safe methods, own methods or check command wrote has Status `DRAFT`, and Reviewed By and Approved By `[PENDING]`. Only the sign-off command sets `APPROVED` and the two names, on the file the helper has just recorded, and no signed-off version's header was copied into a new version. Those three cells, Last Modified and the last two cells of the version's Revision History row hold exactly `DRAFT`, `[PENDING]` or a date written `YYYY-MM-DD`, with no other word or mark, and `status --json` lists no line under the document that names one of them: the sign-off command rewrites those cells, and the helper records no sign-off while one holds anything else.
4. **A signed document was not written over.** If `status --json` showed the document's `signedOff` true before the write, nothing was written. If it showed a sign-off record whose `file` was the current file, that file is unchanged: with `bodyInStep` false the write went to the next minor version, and with `bodyInStep` true or null and `signedOff` false nothing was written and the document's `unfinished` lines were shown. A fault in a header was never answered with a new version. Otherwise the current file was rewritten in place, or version 1.0 written. The completion record is always rewritten in place.
5. **Name, ID and version agree.** The file name is the one `generate-document-id.mjs` gave, and the Document ID, the Version field and the Revision History's last row all carry the same version.
6. **No header field is a guess.** The header is the `document-control-uk.md` partial, with no value taken from the plugin's configuration or the machine's settings. Classification is what the person said, or `[PENDING]`: never the plugin's `default_classification`, and never a default. Owner is the profile's confirmed answer to who keeps the pack up to date, or `[PENDING]`. Review Cycle, Next Review Date and Distribution are what the person said, or `[PENDING]`.
7. **The footer is there**, with Generated by, Generated on, ArcKit Version, Project and Model.
8. **Markdown rules apply outside the markers only.** Heading levels and table shapes between the markers are the helper's, and are never changed to satisfy a rule.
9. **A new project's folder was set up by the helper.** `set-up-folder` was run only for a project created in this run. Its README was not written or reworded by hand, and no file was changed in a project that already existed.

## Every worksheet a command edits

10. **`parse-worksheet --file` reports no problems** for every worksheet made or edited in this run, so no line starting `>` was changed and every field is where the helper reads it.
11. **A worksheet the helper printed was saved unchanged**, and no worksheet that already existed was made again. The helper's output was taken from the command's own output and saved with the Write tool: nothing of the business was written outside its project folder, and any file made in between was inside `food-safety` and is gone.
12. **A worksheet from a different version was brought up to date by the helper, never by hand, and never unseen.** `upgrade-worksheet` was run without `--write` first, and every line it would take out or put in was shown to the person, who agreed before it was run with `--write`. With nobody to ask it was not written: the summary says the worksheet was made by another version of the overlay and gives the dry run. Where it was written, the copy it kept is beside the worksheet, and `parse-worksheet` now reports no problems.
13. **Each name you wrote is one the person gave.** Every `By` and `Decided-by` you wrote in this run is the name the person answering gave in this conversation, or the name given in the request, and its `On` is today's date. Compare each with the conversation.
14. **Nothing was filled in that nobody gave.** Each question nobody answered is still `unanswered`, and the document prints it as **NOT YET ANSWERED**. Each answer taken from a file, or from a request that names nobody, is `proposed`, with `Source` saying where it came from; an own entry has a `Source` line too.
15. **Nothing you suggested was recorded.** No answer, reason, variation, procedure or own method in this run's edits came from you, even as `proposed`; each came from the person, the request or a file the person pointed to. A reply such as "same for the rest" was recorded only for the questions just shown, and only where it answered each in its form.
16. **A missing field stayed missing.** Where a state needs a field the person did not give, the state was left where it was (a method `applies`, an answer `proposed` or `unanswered`, an own entry held as `unanswered` with exactly what the person gave) and the field was not filled in. Each problem `parse-worksheet` reported was put right by asking or by stepping the state back.
17. **A withdrawn entry does not stay confirmed.** An own entry the person said is no longer true was taken out only if they said to; otherwise it was stepped back to `unanswered`, its `By` and `On` emptied and its words kept, and the summary says so.
18. **Dates are the person's.** Every date recorded as an answer or in `EH-review` is the date the person gave, not one worked out from "last month" or "recently".
19. **A method's status is the person's decision.** A method is `not-relevant` or `adapted` only where the person decided it, with their reason and their name in `Decided-by`, and, for `adapted`, what they do instead and how they have proved it works, in their words.
20. **The answers are the person's words.** The form may follow the question's hint (one item per line, `yes` or `no`), but no detail was added and nothing was dropped.

## Own methods and special processes

21. **An entry's title is the person's.** Each title is the person's own name for the method, unchanged; where they gave none, a special process is titled with the pack's name for it, exactly as `Process` holds it, and any other entry with the person's own sentence, cut short at most. No title was reworded, tidied or made up.
22. **Supplied text is word for word.** Each `Supplied-text` holds the business's written procedure with the same words, figures, order, blank lines and indentation. The only thing added is the two-space indent that carries each line after the first.
23. **No procedure was drafted, completed, corrected or improved**, even on request.
24. **`Process` names a special process or food exactly as the worksheet's guidance comment spells it.**
25. **`EH-review` is `pending`**, unless the person gave the date and outcome of the council's review.
26. **A `Limit` has the `Limit-source` the person gave for it**, and no figure or source was supplied by the command.

## Sign-off

27. **The helper recorded it, for the person asking.** `sign-off` exited 0 before the header was changed, in the name of the person making the request, for a version they confirmed or named. On a refusal its messages were shown unchanged, and no worksheet, document or `sign-offs.json` was changed to work round it. Where the person's own sign-off of the file was already recorded, with nothing in it changed since, nothing new was recorded, unless they said a printed copy has been signed since.
28. **The header and any text outside the checked part were shown first.** Before the sign-off command recorded anything, the person was shown the Document Control table and the Revision History rows as they stand in the file, and, if the document's `otherText` in `status --json` was not empty, every line of it; they said in this conversation that they had read them, before `--other-text-read yes` was given. With nobody to ask, nothing was recorded for a document whose `otherText` was not empty.
29. **The sign-off command ended marked or not marked, and said which.** Marked: Status reads `APPROVED`. Reviewed By and Approved By each hold the name, role and date of `signOff` in `status --json`, written `<name>, <role>, <YYYY-MM-DD>`, and the Revision History row holds `<name>, <role>` and that date, with no word added to any of them. This holds for a second person who signs the same file: the rows were rewritten to their record. After the edit `check` exits 0, and `signedOff` and `headerShowsSignOff` are both true: the header shows the sign-off, and nothing else in the file was changed. Not marked: Status reads `DRAFT`, and Reviewed By, Approved By and the Revision History row's two approval cells read `[PENDING]`; nothing else in the file was changed by this run; and the summary gives the document's lines from `status`, unchanged. This holds however the command stopped: a refusal, a stop before recording or marking, or the marking loop. Only the current version's file was touched, and a change the marking made to any other line, between the markers or outside them, was put back before the end was judged. The document was changed only with the Edit tool, and the Build Provenance section core's hook writes was left as the hook wrote it. No header reads `APPROVED` on a document that `status` does not report as signed off.

## The completion record

30. **The unfinished list is the helper's.** The summary shows `status`'s `unfinished` lines unchanged, in their order. A document whose `signedOff` is true and `headerShowsSignOff` is false is said to be signed off with its header still to be marked, and is not put among what is unfinished.
31. **Nothing else changed.** No answer in a worksheet and no other document was changed by the check command. A worksheet was changed only by `upgrade-worksheet --write`, and only in the tool's own wording.

## The summary

32. **For a document a gathering command wrote, it gives the counts from `status --json`**: confirmed, proposed and not yet answered (for own methods, entries confirmed, proposed and unanswered), and each proposed answer, where it came from and who needs to confirm it.
33. **It names every other document now out of step**: for a gathering command, the `unfinished` lines of each other document whose `rendered` is true and `inSync` is false, unchanged.
34. **It says whether `check` passed**, with its message unchanged if it did not.
35. **It says when a document holds text outside its checked part**, giving the lines from `otherText` unchanged, and that whoever signs the document off will be shown them.
36. **It gives a document's status in plain words**: `DRAFT`, or signed off by the named person at the business, with their role and date.
37. **It carries the formatter note**: a program that reformats Markdown may rewrite the tables between the markers and make `check` fail, and the fix is to write the document again with its command, not to edit by hand.
38. **It claims nothing for anyone.** It never calls the business, its food, a method or a document compliant, approved, safe or inspected, and never says or suggests that the Food Standards Agency or a council has reviewed, approved or endorsed anything.
