# UK food safety overlay: checks before the summary

Every command in this overlay runs these checks after its last write and before it shows its summary. Each one is something you can look at: a helper's exit code, a field in `status --json`, a line in a file, or what you yourself wrote in this run against what the person said. A check that does not apply to the command running (the summary checks for a document a command does not write, for example) is skipped. If a check fails, put it right as it says, then look again.

For this overlay's documents these checks take the place of the Common Checks in ArcKit's general quality checklist. The body of each document is printed by the helper, and a general rule about headings or tables must never be met by changing it.

## Every document a command writes

1. **`check` passed.** The last `check --doc CODE --project PROJECT --report FILE` for the file as written exited 0. If it exited 1 for a line of the body, the document was written again from a fresh render, never edited by hand between the markers. This is about a file written in this run: a diary and record sheets file left alone, as **The diary and record sheets** below says, was not written again to make `check` pass. If a command that writes documents (every command of this overlay but the sign-off command) had just written the file and `check` exited 1 for a line of its header, that command put the header back to `DRAFT` and `[PENDING]`; what the sign-off command does with a header is under **Sign-off** below.
2. **The body is the render, whole.** The file holds exactly one `UK-FOOD:BEGIN` line and one `UK-FOOD:END` line, and between them the render output and nothing else. Nothing from the pack appears outside them, and no heading outside them is a section's title or starts with a safe method's identifier and title. Outside them the file holds only what the template gives (the title, Document Control, Revision History, the comment above the body and the footer): you added no summary, note, heading or other text of your own, before the markers or after them. A diary and record sheets file rewritten in place keeps the lines outside its markers as the file held them, as **The diary and record sheets** below says.
3. **The header says DRAFT.** A document written by any command but the sign-off command has Status `DRAFT`, and Reviewed By and Approved By `[PENDING]`. Only the sign-off command sets `APPROVED` and the two names, on the file the helper has just recorded, and no signed-off version's header was copied into a new version. Those three cells, Last Modified and the last two cells of the version's Revision History row hold exactly `DRAFT`, `[PENDING]` or a date written `YYYY-MM-DD`, with no other word or mark, and `status --json` lists no line under the document that names one of them: the sign-off command rewrites those cells, and the helper records no sign-off while one holds anything else.
4. **A signed document was not written over.** If `status --json` showed the document's `signedOff` true before the write, nothing was written. If it showed a sign-off record whose `file` was the current file, that file is unchanged: with `bodyInStep` false the write went to the next minor version, and with `bodyInStep` true or null and `signedOff` false nothing was written and the document's `unfinished` lines were shown. A fault in a header was never answered with a new version. Otherwise the current file was rewritten in place, or version 1.0 written. The completion record is always rewritten in place, and so are the diary and record sheets, unless their file was changed by hand (see **The diary and record sheets** below).
5. **Name, ID and version agree.** The file name is the one `generate-document-id.mjs` gave, and the Document ID, the Version field and the Revision History's last row all carry the same version. A diary and record sheets file rewritten in place keeps its name and its frame: its Document ID and Version agreed with its name before the rewrite, or it was left alone, and a Revision History row a person added is kept whatever version it gives.
6. **No header field is a guess.** The header is the `document-control-uk.md` partial, with no value taken from the plugin's configuration or the machine's settings. Classification is what the person said, or `[PENDING]`: never the plugin's `default_classification`, and never a default. Owner is the profile's confirmed answer to who keeps the pack up to date, or `[PENDING]`. Review Cycle, Next Review Date and Distribution are what the person said, or `[PENDING]`. A diary and record sheets file rewritten in place keeps the header cells it holds, but for those **The diary and record sheets** below names.
7. **The footer is there**, with Generated by, Generated on, ArcKit Version, Project and Model.
8. **Markdown rules apply outside the markers only.** Heading levels and table shapes between the markers are the helper's, and are never changed to satisfy a rule.
9. **A new project's folder was set up by the helper.** `set-up-folder` was run only for a project created in this run. Its README was not written or reworded by hand, and no file was changed in a project that already existed.

## Every worksheet a command edits

10. **`parse-worksheet --file` reports no problems** for every worksheet made or edited in this run, so no line starting `>` was changed and every field is where the helper reads it.
11. **A worksheet the helper printed was saved unchanged**, and no worksheet that already existed was made again. The helper's output was taken from the command's own output and saved with the Write tool: nothing of the business was written outside its project folder, and any file made in between was inside `food-safety` and is gone.
12. **A worksheet from a different version was brought up to date by the helper, never by hand, and never unseen.** `upgrade-worksheet` was run without `--write` first, and every line it would take out or put in was shown to the person, who agreed before it was run with `--write`. With nobody to ask it was not written: the summary says the worksheet was made by another version of the overlay and gives the dry run. Where it was written, the copy it kept is beside the worksheet, and `parse-worksheet` now reports no problems.
13. **Each name you wrote is one the person gave.** Every `By` and `Decided-by` you wrote in this run is the name the person answering gave in this conversation, or the name given in the request, and its `On` is today's date. Compare each with the conversation.
14. **Nothing was filled in that nobody gave.** Each question nobody answered is still `unanswered`, and the document prints it as **NOT YET ANSWERED**. Each answer taken from a file, or from a request that names nobody, is `proposed`, with `Source` saying where it came from; an own entry, and an entry of a list, has a `Source` line too.
15. **Nothing you suggested was recorded.** No answer, reason, variation, procedure or own method in this run's edits came from you, even as `proposed`; each came from the person, the request or a file the person pointed to. A reply such as "same for the rest" was recorded only for the questions just shown, and only where it answered each in its form.
16. **A missing field stayed missing.** Where a state needs a field the person did not give, the state was left where it was (a method `applies`, an answer `proposed` or `unanswered`, an own entry or an entry of a list held as `unanswered` with exactly what the person gave) and the field was not filled in. Each problem `parse-worksheet` reported was put right by asking or by stepping the state back.
17. **A withdrawn entry does not stay confirmed.** An own entry, or an entry of a list, that the person said is no longer true was taken out only if they said to; otherwise it was stepped back to `unanswered`, its `By` and `On` emptied and its words kept, and the summary says so.
18. **Dates are the person's.** Every date recorded as an answer or in `EH-review` is the date the person gave, not one worked out from "last month" or "recently".
19. **A method's status is the person's decision.** A method is `not-relevant` or `adapted` only where the person decided it, with their reason and their name in `Decided-by`, and, for `adapted`, what they do instead and how they have proved it works, in their words.
20. **The answers are the person's words.** The form may follow the question's hint (one item per line, `yes` or `no`), but no detail was added and nothing was dropped.

## Own methods and special processes

21. **An entry's title is the person's.** Each title is the person's own name for the method, unchanged; where they gave none, a special process is titled with the pack's name for it, exactly as `Process` holds it, and any other entry with the person's own sentence, cut short at most. No title was reworded, tidied or made up.
22. **Supplied text is word for word.** Each `Supplied-text` holds the business's written procedure with the same words, figures, order, blank lines and indentation. The only thing added is the two-space indent that carries each line after the first.
23. **No procedure was drafted, completed, corrected or improved**, even on request.
24. **`Process` names a special process or food exactly as the worksheet's guidance comment spells it.**
25. **`EH-review` is `pending`**, unless the person gave the date and outcome of the council's review.
26. **A `Limit` has the `Limit-source` the person gave for it**, and no figure or source was supplied by the command.

## Lists

These apply to every command whose worksheet holds a list of entries and a Kept elsewhere block, such as the cleaning schedule, the suppliers and contacts, and the allergen information.

27. **Each confirmed entry was agreed whole by a named person.** An entry is `confirmed` only where the named person answering agreed it as shown whole in this conversation, or the request stated it whole, each field it needs in terms, by a person who gives their name there. A dish of the allergen information is the exception: it is `confirmed` only in the first way, and one from the request, however stated, is `proposed`. An entry still being given, or given but not yet agreed, is `unanswered`; one from a file, pasted, or from the request without being stated whole by a named person, is `proposed`, with `Source` saying where it came from, or `unanswered` while it lacks a field its list needs.
28. **A changed entry was agreed again.** An entry changed in this run was changed only where the person asked, and only in the fields they changed. Its `State` was set to `unanswered`, with `By` and `On` emptied, and it is `confirmed` again only where the named person agreed it as it now reads.
29. **Kept elsewhere is the person's own statement.** Kept elsewhere holds something only where the person said the business keeps the list somewhere else, with where in their words. It was never offered as a way to finish, and never taken from a file. For the suppliers and contacts, the environmental health team's entry was still asked for. Nothing you said suggests that the record kept elsewhere is held in the document or was checked: a document with Kept elsewhere confirmed and no entry it stands for confirmed says so itself, and the summary does not say otherwise.
30. **Nothing on a list came from you.** No item, method, chemical, product, frequency, amount, contact time, supplier, name, address, telephone number or email address in this run's edits came from you, or from a search; each came from the person, the request or a file the person pointed to, in their words, and a contact detail is exactly as it was given.
31. **A choice is one the worksheet names, made by the person.** A `Frequency` is recorded spelt exactly as the worksheet's guidance comment spells it: the one the person chose, or one the request or a file gave in those words, whatever the letter case. A `Kind` is one of the kinds it names, as the person said, or as the request or a file said in terms. A field that is not for an entry's kind is empty.
32. **An entry's title is the person's**, unchanged. No title was reworded, tidied or made up.
33. **An allergen cell came only from evidence and the person.** Every `contains` written in this run is one that evidence recorded for an ingredient of the dish names: wording of a label, a specification or a supplier's statement the person provided, the person's own word for what a named one lists, or, for a single whole food with nothing added, what the named person who looked at it says. None came from the name of a dish or an ingredient, from what a food usually holds, from another dish's cells, from a search or from anything you know. Every `does not contain` written in this run is the named person's own statement for that dish and that allergen, made after they were told which of the fourteen were found named, with the words, and which were not, once every ingredient in `Ingredients` had its evidence in `Checked-against`, or one the request stated as the command's step 4 allows; none was worked out from what the evidence does not say, and none stands for a different `Ingredients` or `Checked-against` than the dish now has: a change to either emptied every `does not contain` on it, and each was stated again after the change. No `contains` was emptied because evidence was taken out without the person being asked which evidence still recorded lists it, and no allergen recorded as `contains` was put to the person as not found. A `does not contain` that no named person stated in this conversation was emptied before its dish was shown only after the person was told which cells were being emptied, that each held `does not contain`, and why, and the summary names each one still empty because the person did not answer, with its dish and what it held. Every other cell is empty.
34. **A precautionary statement is a note.** A label's statement that the food may contain an allergen, or is made where one is handled, is in `Notes` in the label's own words, and in no cell.
35. **A dish was confirmed as shown whole, with the person's dates and words.** A dish is `confirmed` only where the named person who is there agreed it after being shown every field, each of the fourteen cells among them, with the words each `contains` was read from, and told that an empty cell prints as not confirmed. A dish from the request, even one a named person stated whole with every cell in terms, was recorded `proposed`, with those cells as stated, and was not confirmed until it was shown and agreed. A dish with a cell read from wording, wherever the wording came from, was `proposed` until it was shown and agreed. `Checked-on` is the day the person gave, never assumed to be today. `PPDS` is `yes` or `no` as the person said, or empty. A `Free-from-claim` is the business's own words, and nothing you wrote describes a dish as free from anything or suitable for anyone.
36. **A change stepped back every dish it touched.** Where the person or the request said a dish, an ingredient, a brand or a supplier changed, every dish the search found or the person named was stepped back to `unanswered`, its `By` and `On` emptied and its words kept, and the summary says which dishes need checking again. A dish checked again was confirmed only once each ingredient the change touched had evidence recorded in that check, and holds no `does not contain` the person did not state in it.

## Sign-off

37. **The helper recorded it, for the person asking.** `sign-off` exited 0 before the header was changed, in the name of the person making the request, for a version they confirmed or named. On a refusal its messages were shown unchanged, and no worksheet, document or `sign-offs.json` was changed to work round it. Where the person's own sign-off of the file was already recorded, with nothing in it changed since, nothing new was recorded, unless they said a printed copy has been signed since.
38. **The header and any text outside the checked part were shown first.** Before the sign-off command recorded anything, the person was shown the Document Control table and the Revision History rows as they stand in the file, and, if the document's `otherText` in `status --json` was not empty, every line of it; they said in this conversation that they had read them, before `--other-text-read yes` was given. With nobody to ask, nothing was recorded for a document whose `otherText` was not empty.
39. **The sign-off command ended marked or not marked, and said which.** Marked: Status reads `APPROVED`. Reviewed By and Approved By each hold the name, role and date of `signOff` in `status --json`, written `<name>, <role>, <YYYY-MM-DD>`, and the Revision History row holds `<name>, <role>` and that date, with no word added to any of them. This holds for a second person who signs the same file: the rows were rewritten to their record. After the edit `check` exits 0, and `signedOff` and `headerShowsSignOff` are both true: the header shows the sign-off, and nothing else in the file was changed. Not marked: Status reads `DRAFT`, and Reviewed By, Approved By and the Revision History row's two approval cells read `[PENDING]`; nothing else in the file was changed by this run; and the summary gives the document's lines from `status`, unchanged. This holds however the command stopped: a refusal, a stop before recording or marking, or the marking loop. Only the current version's file was touched, and a change the marking made to any other line, between the markers or outside them, was put back before the end was judged. The document was changed only with the Edit tool, and the Build Provenance section core's hook writes was left as the hook wrote it. No header reads `APPROVED` on a document that `status` does not report as signed off.

## The completion record

40. **The unfinished list is the helper's.** The summary shows `status`'s `unfinished` lines unchanged, in their order. A document whose `signedOff` is true and `headerShowsSignOff` is false is said to be signed off with its header still to be marked, and is not put among what is unfinished.
41. **Nothing else changed.** No answer in a worksheet and no other document was changed by the check command. A worksheet was changed only by `upgrade-worksheet --write`, and only in the tool's own wording.

## The diary and record sheets

42. **A file changed by hand was not written over.** Before anything was written, `check --doc FOODREC --json` was run on the file `recordSheets` named, and the forms were printed afresh only when the Document ID cell was the file's name without `.md` and the Version cell the version in that name, and `ok` was true, `kind` was `stale`, or `kind` was `header` with `bodyInStep` true, whatever `otherText` held; with no file, version 1.0 was written from the template. When `check` sent no `kind`, `bodyInStep` null and `messages`, nothing was written and the messages were shown. In every other case nothing was written unless a person there said, in terms, in the request or in this conversation, that what was typed on the file had been copied or was not wanted, and the file could be read, its marker lines were whole, none of the pack's headings stood outside them, and its Document ID and Version agreed with its name as above; with nobody to answer, nothing was written whatever the request said; and the summary gave what `check` sent, unchanged. A rewrite in place changed only the lines from the `UK-FOOD:BEGIN` line to the `UK-FOOD:END` line, Last Modified, which the summary names with what it held where that was not a date, and each sign-off cell that held anything else, which the summary names with what it held: every other line outside the markers, a line someone added among them, is as it was, and the summary gives each line `otherText` lists.
43. **Nothing was filled in on the forms.** No name, tick, date or signature was written into a form, and nothing you said suggests that a check has been done, that the business does one, or what its own checks should be. The business's own checks are only those the Management worksheet confirms, printed by the helper.
44. **No worksheet was recorded in.** At most a blank profile worksheet was made, saved exactly as the helper printed it. A worksheet's own wording was changed only by `upgrade-worksheet --write`, and no answer was changed.

## The summary

45. **For a document a gathering command wrote, it gives the counts from `status --json`**: confirmed, proposed and not yet answered (for own methods and for a list, entries confirmed, proposed and unanswered), and each proposed answer or entry, where it came from and who needs to confirm it.
46. **It names every other document now out of step**: for a gathering command, the `unfinished` lines of each other document whose `rendered` is true and `inSync` is false, unchanged.
47. **It says whether `check` passed**, with its message unchanged if it did not.
48. **It says when a document holds text outside its checked part**, giving the lines from `otherText` unchanged, and that whoever signs the document off will be shown them. For the diary and record sheets, which nobody signs, it gives instead the lines of their file's `otherText` from `check --json`, with their numbers, unchanged, and says that the command left them as they are.
49. **It gives a document's status in plain words**: `DRAFT`, or signed off by the named person at the business, with their role and date.
50. **It carries the formatter note**: a program that reformats Markdown may rewrite the tables between the markers and make `check` fail, and the fix is to write the document again with its command, not to edit by hand.
51. **It claims nothing for anyone.** It never calls the business, its food, a method or a document compliant, approved, safe or inspected, and never says or suggests that the Food Standards Agency or a council has reviewed, approved or endorsed anything.
52. **An entry recorded from the request is read back.** For the cleaning schedule and the suppliers and contacts, each entry recorded `confirmed` from the request in this run is listed whole in the summary, every field as recorded, an empty one shown as not filled in, and the person is asked to check it against what they sent and to say if any line is wrong. For the allergen information, each dish recorded from the request in this run that is still `proposed` is listed whole in the summary as waiting to be shown and agreed: its number and name, `Ingredients`, `PPDS`, all fourteen cells in the worksheet's order, an empty one shown as not filled in, `Notes`, `Checked-against`, `Checked-on` and `Free-from-claim`, with the statement that it counts only once a named person at the business who is there has been shown it whole and agreed it.
