# 规格说明：目标跟踪模型的通用 UI

**日期：** 2026-08-05
**状态：** 草案
**作者：** Mark Craddock（通过 Claude Code）
**撰写时的 ArcKit 版本：** 6.8.0

> 本文档是 [`2026-08-05-object-tracking-ui-spec.md`](2026-08-05-object-tracking-ui-spec.md) 的简体中文译本。如两个版本存在出入，以英文原版为准。

## 1. 摘要

本文档规定了一个通用的、与模型无关的用户界面，用于运行、检视和修正多目标跟踪
（Multi-Object Tracking，MOT）模型的输出。该 UI 位于任意跟踪器之前——只要该跟踪器
消费视频（文件或直播流）并输出按帧分组、归属于持久轨迹的检测结果即可，例如
SORT、DeepSORT、ByteTrack、OC-SORT 或专有模型。本规格不假设任何特定的模型架构、
类别体系或部署目标。

该 UI 承担三项工作：

1. **运行（Operate）** —— 将视频输入模型、配置模型，并针对直播或录制素材实时观看
   跟踪过程。
2. **检视（Inspect）** —— 理解模型的行为：跟踪了哪些目标、身份在何处发生切换或
   断裂、置信度如何。
3. **修正（Correct）** —— 修复跟踪器的错误（合并、拆分、重新标注、删除轨迹），并
   将修正结果导出为真值（ground truth）或下游输入。

## 2. 目标与非目标

### 目标

- 通过定义好的集成契约（第 8 节）适配任意跟踪模型。
- 在同一界面中同时支持**离线**模式（录制视频、批量结果）与**实时**模式（流式
  推理）。
- 让轨迹身份清晰可读：人工可以在一分钟内跟完整段视频中的某一个目标。
- 支持人在回路（human-in-the-loop）修正，提供完整的撤销能力和可审计的编辑历史。
- 在有真值数据时展示跟踪质量指标（MOTA、IDF1、HOTA）。
- 满足 WCAG 2.2 AA 无障碍要求。

### 非目标

- 不涉及模型的训练或微调。UI 仅消费模型输出。
- 不支持帧级多边形/分割标注。支持的几何形状为边界框（可选支持旋转框/关键点）。
- 不支持多摄像头跨视角重识别。每个会话仅一路视频源；多摄像头列为未来扩展
  （第 12 节）。
- 除播放所需之外，不涉及视频剪辑、转码或存储管理。

## 3. 用户

| 角色 | 主要工作 | 关键需求 |
|------|----------|----------|
| 机器学习工程师 | 调试跟踪器行为 | 帧级精确拖动、按轨迹的置信度曲线、ID 切换高亮、原始载荷检视 |
| 标注员 / QA 审核员 | 修正轨迹以产出真值 | 高效的键盘驱动审核、合并/拆分工具、进度跟踪、导出 |
| 运维操作员 | 监控直播画面 | 低延迟叠加层、按关注类别/区域告警、极简配置界面 |
| 产品 / 分析人员 | 评估是否满足业务需要 | 汇总指标、类别分布、可导出的报告 |

## 4. 概念与术语

- **检测（Detection）** —— 单帧中的一个边界框：类别标签、几何信息、置信度分数。
- **轨迹（Track）** —— 跨帧共享同一持久**轨迹 ID** 的一串检测，代表同一个物理
  目标。
- **ID 切换（ID switch）** —— 跟踪器在序列中途将某目标的检测重新分配给了另一个
  轨迹 ID。
- **轨迹断裂（Fragmentation）** —— 一个物理目标被多条中间有间隙的短轨迹覆盖。
- **遮挡（Occlusion）** —— 目标被遮住；跟踪器可能滑行（预测）或丢弃轨迹。
- **真值（Ground truth）** —— 用于给模型打分的人工核验轨迹。
- **会话（Session）** —— 一路视频源及其跟踪结果、配置和编辑历史。

## 5. 信息架构

```text
应用
├── 会话（列表 / 创建 / 打开）
└── 会话工作区
    ├── 查看器      —— 视频画布 + 叠加层 + 播放控制
    ├── 时间线      —— 拖动条下方的逐轨迹泳道
    ├── 轨迹检视器  —— 所选轨迹的详情与编辑工具
    ├── 配置        —— 模型、阈值、类别、区域
    ├── 指标        —— 质量看板（需要真值）
    └── 导出        —— 修正后的轨迹、片段、报告
```

查看器、时间线和轨迹检视器构成默认的三栏工作区。配置、指标和导出以次级视图
打开，不会丢失播放位置和选择状态。

## 6. 功能需求

需求编号遵循 ArcKit 约定（`FR-xxx` 功能需求、`NFR-xxx` 非功能需求、`INT-xxx`
集成需求、`DR-xxx` 数据需求）。

### 6.1 视频接入与播放

- **FR-001** 加载录制视频文件（基线为 MP4/H.264；WebM 可选），或连接直播流
  （RTSP/WebRTC/HLS，视部署而定）。
- **FR-002** 播放控制：播放/暂停、逐帧步进（±1）、跳转（±1 秒、±10 秒）、播放
  速率 0.1×–8×、对标记区间循环播放。
- **FR-003** 帧级精确的拖动条，显示当前帧号和时间戳；拖动时叠加层同步更新
  （不得出现过期的框）。
- **FR-004** 实时模式下显示端到端延迟（采集 → 叠加显示）和"LIVE"指示；允许暂停
  进入缓冲回看模式并返回直播。

### 6.2 叠加层渲染

- **FR-010** 将每个可见检测渲染为边界框，颜色按轨迹分配，且在该轨迹 ID 的生命
  周期内保持稳定。
- **FR-011** 每个框的标签内容可配置：轨迹 ID、类别、置信度——三者可独立开关。
- **FR-012** 可开关的**轨迹尾迹**渲染：目标质心在最近 N 帧内的路径（N 可配置，
  默认 30）。
- **FR-013** 置信度过滤：滑块可隐藏低于阈值的检测，无需重新运行模型。
- **FR-014** 类别过滤：按类别显示/隐藏；过滤同时一致地作用于叠加层、时间线和
  轨迹列表。
- **FR-015** 区分**预测/滑行**框（遮挡期间的跟踪器输出）与有检测支撑的框，例如
  虚线描边与实线描边。
- **FR-016** 叠加密度控制：并发框数 >50 时标签收缩为仅显示 ID；>200 时框不再
  显示标签，除非悬停。

### 6.3 轨迹选择与检视

- **FR-020** 点击画布中的框或时间线中的泳道即可选中轨迹；选中后该轨迹在所有
  位置高亮、其余轨迹变暗（"聚焦模式"，可开关）。
- **FR-021** 轨迹检视器显示：轨迹 ID、类别、首帧/末帧、时长、间隙数、平均/最低
  置信度，以及置信度随时间变化的迷你曲线。
- **FR-022** "跟随"模式：播放时保持所选轨迹居中（数字平移/缩放），直至解除。
- **FR-023** 跳转导航：所选轨迹的上一次/下一次出现、下一个被标记的事件
  （第 6.5 节）。
- **FR-024** 原始载荷视图：所选轨迹或当前帧的底层 JSON，可复制。

### 6.4 时间线

- **FR-030** 每条轨迹一条水平泳道，与拖动条对齐；泳道分段表示存在，间隙表示
  缺失。
- **FR-031** 泳道排序选项：首次出现（默认）、时长、类别、轨迹 ID。
- **FR-032** 泳道上的事件标记：ID 切换、低置信度区间、区域进入/离开。
- **FR-033** 超过约 100 条轨迹时时间线启用虚拟化；小地图汇总整段视频的轨迹
  密度。

### 6.5 模型事件与标记

- **FR-040** UI 计算并标记**待审核项**：间隙超过阈值的轨迹、几何位置突变、同一
  轨迹内的类别翻转，以及暗示 ID 切换的近乎同时的"一止一起"轨迹对。
- **FR-041** 标记以可过滤的审核队列呈现；键盘 `j`/`k` 逐项浏览，并将查看器定位
  到每个事件。
- **FR-042** 实时模式下，用户自定义的告警规则（类别 + 可选区域 + 可选停留时长）
  触发可视告警和事件日志条目；破坏性/联动执行类副作用不在范围内。

### 6.6 修正工具（离线模式）

- **FR-050** **合并**：将两条或多条轨迹合并为一个 ID；重叠帧按较高置信度取舍，
  若双方均经人工编辑则弹出冲突确认。
- **FR-051** **拆分**：在当前帧将一条轨迹切分为两个 ID。
- **FR-052** **重新标注**：修改轨迹类别，可作用于整条轨迹或从当前帧起。
- **FR-053** **删除**：删除整条轨迹或其中一段帧范围（误检）。
- **FR-054** **调整**：移动/缩放某一帧上的框；可选择在选定范围内对调整量做
  插值。
- **FR-055** **新建**：绘制新框并通过插值将其扩展到多帧，以覆盖漏检目标。
- **FR-056** 每次编辑均可撤销/重做（会话级历史，至少 200 步），并记入编辑日志：
  谁、何时、做了什么、影响哪些帧。
- **FR-057** 经过编辑的轨迹与模型原始输出在视觉上可区分，并维护每条轨迹的来源
  状态：`model`（模型）、`edited`（已编辑）、`verified`（已核验）。

### 6.7 配置

- **FR-060** 从已配置的后端注册表中选择模型，显示名称、版本和支持的类别。
- **FR-061** 将后端声明的可调参数（第 8 节）呈现为带类型的控件：检测阈值、
  NMS/IoU 阈值、最大滑行帧龄、类别白名单。未知参数按其 JSON Schema 通用渲染。
- **FR-062** 使用更改后的设置对已加载视频重新运行跟踪；结果在会话内以**运行
  （run）**为单位管理版本，可并排比较（两次运行的 A/B 叠加，用颜色区分）。
- **FR-063** 区域编辑器：在画面上绘制命名多边形区域，用于过滤、告警和指标。

### 6.8 指标（需要真值）

- **FR-070** 导入真值（MOT Challenge 格式及原生导出格式，第 9 节），或将一次
  全部为 `verified` 状态的运行提升为真值。
- **FR-071** 看板：MOTA、MOTP、IDF1、HOTA、ID 切换数、轨迹断裂数、FP/FN 计数
  ——整体与分类别。
- **FR-072** 同一会话内各次运行之间的指标差值。
- **FR-073** 点击任一汇总数字（如"17 次 ID 切换"）即可在审核队列中打开对应的
  底层事件。

### 6.9 导出

- **FR-080** 轨迹导出格式：原生 JSON（第 9 节）、MOT Challenge CSV、COCO-video
  JSON。
- **FR-081** 导出范围选项：全部轨迹、过滤结果集、选中轨迹或某段帧范围。
- **FR-082** 对标记区间导出烧录叠加层的视频（离线渲染，汇报进度）。
- **FR-083** 将指标看板导出为独立报告（HTML 或 PDF）。

## 7. 交互设计

### 7.1 键盘映射（默认值，可重映射）

| 按键 | 操作 |
|------|------|
| `Space` | 播放 / 暂停 |
| `←` / `→` | 后退 / 前进一帧 |
| `Shift+←/→` | 跳转 1 秒 |
| `J` / `K` | 上一个 / 下一个被标记事件 |
| `F` | 对当前选择开关跟随模式 |
| `M` | 合并所选轨迹 |
| `S` | 在播放头处拆分所选轨迹 |
| `Delete` | 删除所选内容（删除整条轨迹时需确认） |
| `Ctrl/Cmd+Z` / `Shift+Ctrl/Cmd+Z` | 撤销 / 重做 |
| `1`–`9` | 切换类别过滤 |
| `Esc` | 清除选择 / 退出模式 |

### 7.2 状态与反馈

- **空会话**：突出显示接入视频的引导入口；提供示例片段。
- **处理中**：批量运行显示确定性进度（已处理帧数 / 总帧数、预计剩余时间）；
  跟踪结果随产出流式进入时间线，而不是等全部完成后才显示。
- **实时降级**：若推理落后于视频流，UI 丢弃叠加帧（绝不无限缓冲），显示
  "模型滞后：X 秒"徽标，并记录降级事件。
- **后端断连**：已接收结果的回放继续可用；出现带重试/退避状态的重连横幅；编辑
  在重连前保留在本地。
- **冲突**：多用户部署中对同一轨迹的并发编辑按"后写者胜"解决，并以非阻塞的
  轻提示（toast）链接到编辑日志中的两个版本。

## 8. 模型集成契约（INT）

UI 通过一层轻量适配器与跟踪后端通信。任何能满足该契约的模型均可接入。

- **INT-001** `GET /models` —— 列出可用模型：`id`、`name`、`version`、
  `classes[]`、`tunables`（供 FR-061 使用的 JSON Schema）。
- **INT-002** `POST /runs` —— 启动一次运行：视频源（上传引用或流 URL）、模型
  id、参数取值。返回 `run_id`。
- **INT-003** 结果交付 —— 流式（WebSocket/SSE，每条消息一个帧批次）或轮询
  （`GET /runs/{id}/results?from_frame=`）二选一。两种方式携带相同的帧载荷
  （第 9 节）。
- **INT-004** `DELETE /runs/{id}` —— 取消一次运行。
- **INT-005** 时间戳：每个帧载荷携带相对于视频源起点的 `frame_index` 和
  `timestamp_ms`；直播源还需携带采集时的墙钟时间，以便计算延迟（FR-004）。
- **INT-006** 适配器必须容忍乱序和重复的帧载荷（以 `run_id` + `frame_index`
  实现幂等）。
- **INT-007** UI 与后端之间的鉴权由部署方定义（基线为 token 请求头）；UI 绝不
  将凭据嵌入导出产物。

## 9. 数据模型（DR）

- **DR-001** 原生轨迹交换格式（JSON）：

```json
{
  "session_id": "uuid",
  "run_id": "uuid",
  "source": { "type": "file|stream", "uri": "...", "fps": 30.0, "width": 1920, "height": 1080 },
  "model": { "id": "bytetrack-x", "version": "1.4.2" },
  "tracks": [
    {
      "track_id": 17,
      "class": "vehicle",
      "provenance": "model|edited|verified",
      "detections": [
        {
          "frame_index": 1042,
          "timestamp_ms": 34733,
          "bbox": [x, y, w, h],
          "confidence": 0.91,
          "coasted": false
        }
      ]
    }
  ],
  "edits": [
    { "op": "merge", "actor": "user@example.com", "at": "2026-08-05T10:12:00Z", "detail": { "from": [17, 22], "into": 17 } }
  ]
}
```

- **DR-002** 坐标为源分辨率下的像素值，原点在左上角；所有显示缩放由 UI 负责。
- **DR-003** 轨迹 ID 在一次运行内唯一；合并时保留存续 ID，被吸收的 ID 记入编辑
  日志。
- **DR-004** 会话持久化内容：视频源引用、全部运行、编辑历史、区域，以及 UI
  状态（过滤条件、最后位置）。视频内容按引用保存而非复制，除非部署方选择托管
  存储。
- **DR-005** 导出产物的保留期限与密级遵循所在组织的数据治理策略；UI 在导出物上
  加盖会话 ID、运行 ID、模型版本和导出时间，以保证可追溯性。

## 10. 非功能需求

- **NFR-P-001** 在中端笔记本电脑上，叠加层渲染在并发框数 ≤200 时可维持最高
  60 fps 的源帧率（使用 canvas/WebGL 渲染，而非每框一个 DOM 元素）。
- **NFR-P-002** 对已加载结果，拖动到渲染的延迟 ≤100 毫秒。
- **NFR-P-003** 实时模式下 UI 侧测得的端到端叠加延迟目标 ≤500 毫秒（模型延迟
  不计入 UI 预算，但需展示）。
- **NFR-P-004** 通过虚拟化和多级细节（level-of-detail）渲染，时间线和轨迹列表
  在 10,000 条轨迹 / 100 万个检测规模下保持响应（交互 ≤100 毫秒）。
- **NFR-SEC-001** 与后端的全部通信走 TLS；不向第三方服务发送视频帧或结果。
- **NFR-SEC-002** 编辑日志条目仅追加（append-only）且可归因（用户身份来自部署
  方的认证提供方）。
- **NFR-A11Y-001** WCAG 2.2 AA：完整的键盘可操作性、可见的焦点指示，以及叠加层
  状态的文字替代（"轨迹 17，车辆，于 00:34 进入区域 Gate-A"）。
- **NFR-A11Y-002** 轨迹颜色取自对色觉缺陷友好的安全色板；颜色绝不是唯一的身份
  信号（ID 标签始终可用）。
- **NFR-A11Y-003** 尊重 `prefers-reduced-motion`：尾迹和跟随模式动画降级为静态
  呈现。
- **NFR-I18N-001** 所有 UI 文案外置；时间戳按用户区域设置渲染，同时始终提供
  相对于视频源的时间码。
- **NFR-C-001** 浏览器基线：主流常青浏览器的最近两个版本；不依赖任何插件。

## 11. 验收标准（代表性）

1. 给定一段 10 分钟、30 fps 的视频和一次已完成的运行，用户可在三次交互内选中
   画面上的任意目标并查看其完整轨迹生命周期（时间线泳道 + 跟随模式）。
2. 给定一次含已知 ID 切换的运行，审核队列将其标记，按 `K` 可定位到该事件，
   并通过两条轨迹的合并（FR-050）解决它；该合并在编辑日志中可见，且可通过撤销
   还原。
3. 给定该视频的真值，指标看板报告 MOTA/IDF1/HOTA；更改检测阈值重新运行后产生
   第二次运行，并展示两次运行的指标差值（FR-072）。
4. 给定一路直播 RTSP 源且后端推理落后时，叠加层丢帧、显示滞后徽标，且在一小时
   的会话中内存绝不无限增长。
5. 标注员仅用键盘即可端到端完成第 2 条验收标准。
